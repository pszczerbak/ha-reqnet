# Troubleshooting

## REQNET does not appear under Add Integration

Check that the directory is exactly `/config/custom_components/reqnet`, that it contains `manifest.json`, and restart Home Assistant Core. Review **Settings → System → Logs** for the `reqnet` domain.

## Telemetry unavailable or missing updates

1. Confirm Home Assistant's official MQTT integration is connected to the broker.
2. Confirm the **REQNET device itself** is configured to publish to this same additional broker; Home Assistant MQTT setup alone does not configure the device.
3. Check the device's local REST API connectivity from the Home Assistant network.
4. Confirm the correct Wi-Fi MAC address, not an unrelated Ethernet MAC.
5. Avoid publishing test messages with `retain=true`.

## Bypass reports an unknown option

The documented bypass readback includes `0`, `1`, `2`, and `3`. Both `2` (damper closed) and `3` (damper open) are automatic control. Version 0.2.0+ supports them. Unknown codes should be investigated rather than guessed.

## Error log count is unknown

The API sometimes returns only a success flag without `Rows`. That is an *unknown log count*, not proof that the log is empty. Active notification code and stored error history are separate data sources.

## Additional MQTT broker provisioning fails

Confirm the target broker host and port are reachable **from REQNET**, the credentials exist on that broker, the device's REST endpoint is reachable, and the explicit plaintext HTTP acknowledgement was checked. The integration does not save the broker password or configure Home Assistant's own MQTT integration. Do not include credentials in issue reports.

## Automation IDs and upgrades

Entity IDs are suggestions generated by the integration. Existing IDs can differ if you renamed them or if HA detected a naming collision. Use the entity registry to confirm actual IDs and review automation dependencies before removing old YAML entities.
